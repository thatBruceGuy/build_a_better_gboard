================== NOTES ON READING THIS ==================

The "keys" column counts detected keys in that row. Letter rows show 9 or 10.
Lower counts mean either a bottom row (shift/?123/space/enter merge into fewer
wide keys) or an icon strip. FUTO's row 3 showing 7 and row 4 showing 2 is the
detector merging adjacent wide keys at the default threshold; the row geometry
(top, bottom, pitch) is unaffected and is what matters here.

Samsung's band 2 (the number row) has no pitch figure because band 1 above it
was excluded as chrome, so there is no preceding key row to measure from. Its
real pitch against the row below is 152px.

Gboard's row 1 is a real number row with keycaps. FUTO has no number row at all
in this configuration; its digits are superscript hints on the QWERTY row, which
is the single biggest reason it can beat Gboard on total height.

The three totals, for reference:
    Samsung  1034px / 295dp
    Gboard    845px / 241dp
    FUTO     ~821px / ~235dp  (computed; the screenshot is cropped)
    Target    595px / 170dp

One caveat on the FUTO column, which matters when reading it as "stock": see
the height-multiplier note in README.md. The measured 35.1dp pitch is not
FUTO's default -- it is FUTO with a height multiplier of roughly 0.58 already
set in settings. FUTO's own default on this phone works out to about 61dp.
